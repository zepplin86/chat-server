# 1단계 사고 과정: 서버 한 대로 대화가 되기까지

코드에는 "무엇을 했는지"만 남는다. 이 문서는 "왜 그렇게 했는지"와 "무엇을 일부러 하지 않았는지"를 남긴다.

1단계는 한 번에 만들지 않았다. 아주 작은 것부터 시작해 일곱 번에 걸쳐 조금씩 붙였다. 매번 "지금 무엇이 안 되는가"를 먼저 보고, 그것 하나만 고쳤다.

> 이 문서는 1단계가 끝난 뒤에 커밋 기록과 코드를 보고 정리했다. 각 걸음은 커밋 하나와 짝을 이룬다.

## 한눈에 보기

| 걸음 | 그때 안 되던 것 | 그래서 넣은 것 | 커밋 |
|---|---|---|---|
| 1 | 아무것도 없다 | 화면 한 장을 보여 주는 서버 | `0df0ea5` |
| 2 | 화면이 서버와 말을 주고받지 못한다 | WebSocket, 보낸 말 되돌려 주기 | `d759b6f` |
| 3 | 내 말이 나에게만 돌아온다 | 방송 채널 | `17d9da0` |
| 4 | 서버 안에서 무슨 일이 일어나는지 안 보인다 | 로그 | `c3e3307` |
| 5 | 누가 한 말인지 모른다 | 이름 | `bab8e1c` |
| 6 | 늦게 들어온 사람은 앞의 대화를 못 본다 | 대화 기록 (메모리) | `5048e93` |
| 7 | 파일 하나에 모든 것이 섞여 있다 | 모듈로 나누기 | `ae27216` |

## 걸음 1. 화면 한 장

가장 먼저 만든 것은 채팅이 아니다. 브라우저로 접속하면 화면 한 장이 나오는 서버다.

```
브라우저 ──▶ 서버 ──▶ 화면(HTML) 한 장
```

채팅 기능이 하나도 없어도 이것은 "처음부터 끝까지 돌아가는 것"이다. 포트가 열리는지, 브라우저가 붙는지를 여기서 확인해 두면, 다음 걸음에서 문제가 생겼을 때 원인이 새로 넣은 것 하나로 좁혀진다.

화면 파일은 실행 파일 안에 넣었다(`include_str!`). 파일을 따로 배달하는 장치를 만들지 않기 위해서다.

## 걸음 2. WebSocket: 서버와 말을 주고받는다

**안 되던 것**: 화면은 보이지만 서버와 계속 말을 주고받을 방법이 없다.

보통의 웹 요청(HTTP)은 "브라우저가 묻고, 서버가 답하고, 끝"이다. 서버가 먼저 말을 걸 수 없다. 채팅은 남이 보낸 말이 내가 묻지 않아도 도착해야 한다.

**넣은 것**: WebSocket. 한 번 연결하면 끊을 때까지 열려 있고, 양쪽 모두 아무 때나 보낼 수 있는 통로다.

이 걸음에서는 받은 말을 **보낸 사람에게 그대로 되돌려 주기만** 했다. 다른 사람에게는 전달하지 않는다. 통로가 열리고 말이 오가는지만 먼저 확인하려는 것이다.

## 걸음 3. 방송 채널: 모두에게 뿌린다

**안 되던 것**: 브라우저 두 개를 열어도 서로의 말이 보이지 않는다. 연결마다 따로 놀기 때문이다.

연결 하나는 자기 통로만 안다. 다른 연결의 통로에 직접 쓸 수 없다. 연결들 사이를 잇는 무언가가 필요하다.

**넣은 것**: 방송 채널(`tokio::sync::broadcast`). 한쪽에서 넣으면 구독 중인 모두가 받는 통로다.

```
철수 ──▶ ┐                ┌──▶ 철수
         ├─▶ 방송 채널 ─▶ ┤
영희 ──▶ ┘                └──▶ 영희
```

여기서 각 연결이 하는 일이 둘로 늘었다.

1. 이 사람이 보낸 말을 받아 방송 채널에 넣는다.
2. 방송 채널에서 온 말을 이 사람에게 전달한다.

둘 중 어느 쪽이 먼저 일어날지 모른다. 그래서 **둘을 동시에 기다린다**(`tokio::select!`). 1단계 코드에서 가장 낯선 부분이 이것이고, 이후 모든 단계에서 이 모양이 그대로 남는다.

방송 채널은 보낸 본인에게도 돌려준다. 그래서 걸음 2의 "되돌려 주기" 코드는 따로 둘 필요가 없어졌다.

## 걸음 4. 로그: 안에서 일어나는 일을 본다

**안 되던 것**: 화면에는 결과만 보인다. 메시지가 서버에 도착했는지, 몇 명에게 갔는지 알 수 없다.

**넣은 것**: 접속, 받음, 방송, 전달, 종료를 터미널에 한 줄씩 찍는다. 연결마다 번호표를 붙여 누구의 일인지 구분한다.

이것은 기능이 아니다. 하지만 다음 걸음들에서 "왜 안 오지?"를 추측 대신 눈으로 확인하게 해 준다. 그래서 기능을 더 붙이기 전에 넣었다.

번호표는 여러 연결이 동시에 뽑아도 겹치지 않아야 한다. 그래서 그런 용도의 숫자 타입(`AtomicU64`)을 썼다.

## 걸음 5. 이름: 누가 한 말인가

**안 되던 것**: 말은 오가는데 누가 했는지 모른다.

**넣은 것**: 화면이 먼저 이름을 묻고, 접속 주소 뒤에 붙여 보낸다(`/ws?name=철수`). 서버는 말에 이름을 붙여 뿌린다.

이름을 붙이려니 메시지가 글자 한 줄로는 부족해졌다. "누가"와 "무슨 말"을 나눠 담아야 한다. 그래서 JSON 을 쓰기 시작했다.

```json
{"name": "철수", "body": "안녕"}
```

**일부러 하지 않은 것**: 이름 확인. 아무나 아무 이름을 쓸 수 있고, 같은 이름 둘이 들어와도 막지 않는다. 진짜 로그인은 계정을 저장할 곳이 있어야 하는데 아직 저장소가 없다. 2단계의 일이다.

## 걸음 6. 대화 기록: 늦게 온 사람도 본다

**안 되던 것**: 나중에 들어온 사람은 빈 화면을 본다. 방송 채널은 그 순간 듣고 있는 사람에게만 전달하고, 지나간 말은 버린다.

**넣은 것**: 지금까지의 말을 목록(`Vec`)에 모아 두고, 새로 온 사람에게 먼저 보내 준다.

여러 연결이 이 목록을 동시에 건드린다. 그래서 한 번에 하나만 들어갈 수 있게 잠금(`Mutex`)으로 감쌌다.

### 잠금 하나로 두 가지를 묶은 이유

새로 온 사람은 두 가지를 해야 한다. 지난 대화를 복사하고, 방송 구독을 시작한다. 이 둘 사이에 틈이 있으면 문제가 생긴다.

- 복사를 먼저 하면: 복사와 구독 사이에 온 말을 **놓친다**.
- 구독을 먼저 하면: 그 사이에 온 말을 기록에서 한 번, 방송으로 한 번, **두 번** 받는다.

그래서 둘을 같은 잠금 안에서 한다. 보내는 쪽도 "기록에 추가"와 "방송"을 같은 잠금 안에서 한다. 이러면 틈이 없고, 기록 순서와 방송 순서도 같아진다.

이 방법은 기록이 메모리에 있어서 가능했다. 복사가 순식간에 끝나므로 잠금을 쥐고 있어도 괜찮다. 2단계에서 기록이 DB 로 가면 이 방법을 쓸 수 없게 된다. 그 이야기는 [2단계 문서](02-postgres.md)에 이어진다.

## 걸음 7. 모듈로 나누기

**안 되던 것**: 동작에는 문제가 없다. 다만 파일 하나에 조립, 함께 쓰는 상태, 연결 처리가 섞여 있어 `main` 이 무엇을 하는지 한눈에 들어오지 않는다.

**넣은 것**: 파일을 셋으로 나눴다. 동작은 그대로다.

| 파일 | 맡은 일 |
|---|---|
| `main.rs` | 조립만 한다. 상태를 만들고, 주소와 함수를 잇고, 포트를 연다 |
| `state.rs` | 모든 연결이 함께 쓰는 것 |
| `ws.rs` | 연결 하나를 맺고 끝까지 담당하는 코드 |

**일부러 하지 않은 것**: 연결 처리 함수(`chat`) 안을 더 잘게 쪼개기. "보낸 말 받기"와 "방송 듣기"를 동시에 기다리는 한 덩어리가 한 화면에 보이는 편이 흐름을 읽기 쉽다.

나눈 시점도 의도한 것이다. 처음부터 파일을 나눠 놓고 시작하지 않았다. 한 파일로 끝까지 돌아가게 만든 뒤, 덩어리가 보이고 나서 나눴다.

## 1단계가 끝났을 때의 모양

```
브라우저 ──WebSocket──▶ 서버 ┬─ 방송 채널 (지금 접속한 사람에게 전달)
                            └─ 대화 기록 (나중에 온 사람에게 보여 줌)
                               둘 다 메모리에 있다
```

프로세스 하나, 외부 의존 없음. `cargo run` 한 줄로 뜬다.

## 1단계의 한계

- **서버를 끄면 대화가 사라진다.** 기록이 메모리에만 있기 때문이다. → 2단계로 가는 이유
- 이름을 아무나 아무렇게나 쓸 수 있다.
- 방이 하나뿐이다.
- 느린 사람이 메시지를 256개 넘게 밀리면 그만큼 놓친다. 지금은 로그만 찍고 넘어간다. → 8단계에서 다룬다

첫 번째 한계는 직접 볼 수 있다. 대화를 몇 줄 나눈 뒤 서버를 껐다 켜고 다시 접속하면 빈 화면이 나온다.

```bash
git switch --detach v0.1.0   # 1단계 코드로 가기
cargo run
git switch -                 # 원래 브랜치로 돌아오기
```
